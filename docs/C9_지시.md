# C9 작업 지시: 댓글 추천·비추천 + 3개만 보이기·정렬 (11/16 채팅 결정)

> PROJECT.md 4.11 표의 C9 행이 가리키는 지시서. 결과는 **PROJECT.md 4.11**에 기록한다.
> 공통 규칙 그대로: PROJECT.md와 이 문서를 먼저 다시 읽기 / 화면 글자는 `textContent` / 새 입력은 서버 검증 / 테스트 추가 + 기존 150개 통과 / 지시에 없던 결정은 따로 목록으로.

## 무엇을
- 상세 페이지 댓글마다 **👍 추천 / 👎 비추천** 버튼과 숫자 (예: `👍 3` `👎 1`)
- **남이 쓴 댓글에만 누를 수 있음.** 내 댓글은 숫자만 보이고 버튼은 꺼짐(누를 수 없음)
- 누르면 그 숫자가 **1 올라감**. 한 사람이 댓글 하나에 **추천이나 비추천 중 하나만**
  - 👍 누름 → 👍 +1 (버튼 강조)
  - 👍 다시 누름 → 취소 (👍 −1)
  - 👍 상태에서 👎 누름 → 👍 −1, 👎 +1 (바꾸기)
- 목록 순서는 지금처럼 최신순 그대로

## DB (`scripts/init_db.py`, 이미 있는 DB에도 붙게)
- `comment_votes`(comment_id → comments ON DELETE CASCADE, user_id → users ON DELETE CASCADE, value INTEGER CHECK(value IN (1, -1)), created_at, PRIMARY KEY(comment_id, user_id))
- 댓글을 지우면 그 댓글의 추천·비추천도 같이 지워짐

## API
- `PUT /api/comments/{id}/vote` `{ "value": 1 | -1 | 0 }` (0 = 취소) → `{ likes, dislikes, my_vote }`
  - 내 댓글 → 403, 없는 댓글 → 404, 그 외 값 → 422
  - 같은 값을 다시 보내도 결과는 같음 (화면은 "다시 누름 = 취소"를 0으로 보냄)
- `GET /api/games/{id}/comments` 각 댓글에 `likes`, `dislikes`, `my_vote`(1 / −1 / 0) 추가. 개수는 한 번의 쿼리로 모아서 계산 (댓글마다 쿼리 X)
- `POST`·`PATCH` 응답의 댓글에도 같은 필드 (새 댓글은 0·0·0)

## 화면 (`static/js/game.js`, `static/css/pages.css`)
- 댓글 아래쪽(고치기·지우기 줄과 같은 줄 또는 바로 위)에 버튼 2개. `aria-pressed`로 눌림 상태, 눌린 버튼은 강조 색(라이트/다크 기존 변수)
- 누르면 **숫자를 바로 바꾸고**(기다리지 않게) 서버 응답 숫자로 맞춤. 실패하면 원래 숫자로 되돌리고 기존 오류 안내 방식으로 알림
- 요청 중에는 그 댓글의 버튼을 잠깐 꺼서 연타 방지
- 내 댓글: 버튼 `disabled` + `title="내 댓글에는 누를 수 없어요"`
- 버튼 크기는 모바일에서 누르기 쉽게(최소 32px)

## 보안·개인정보
- 요청 제한: 사용자당 **분당 30회** (429)
- 누가 눌렀는지는 화면·API에 보이지 않음 (숫자와 내 상태만)
- "내 데이터 내려받기"에 내가 누른 추천·비추천 포함, "내 데이터 삭제"하면 같이 삭제, "추천 기록 초기화"는 건드리지 않음
- 댓글 추천은 **게임 추천 엔진(태그 점수)에 반영하지 않음**

## 테스트 (예)
추천·비추천·취소·바꾸기 숫자 / 내 댓글 403 / 없는 댓글 404 / 값 2·"a" 422 / 같은 값 두 번 / 목록의 likes·dislikes·my_vote / 다른 사용자 시점의 my_vote / 댓글 삭제 시 함께 삭제 / 사용자 삭제 시 함께 삭제 / 요청 제한 429 / 내려받기에 포함

## C9-b. 댓글 3개만 보이기 + 전체 보기 + 정렬 (11/16 채팅 추가, 추천·비추천 다음에)

### 처음 화면 (접힌 상태)
- 상세 페이지 댓글 영역에는 **추천(👍) 많은 순 상위 3개만** 보인다. 👍가 같으면 최신순
- 댓글이 4개 이상이면 아래에 **"댓글 N개 전체 보기"** 버튼. 3개 이하면 버튼 없음
- 입력창·제목("댓글 N")은 지금 자리 그대로
- 내가 방금 쓴 댓글은 순위와 상관없이 접힌 목록 맨 위에 잠깐 보여줌(새로고침하면 원래 규칙) — 썼는데 안 보이면 안 써진 줄 알기 때문

### 전체 보기 (펼친 상태)
- 버튼을 누르면 **같은 자리에서 펼쳐짐**(새 페이지·팝업 아님). 펼친 뒤 위에 **정렬 칩 3개: 최신순 · 등록순 · 추천순**, 맨 아래 "접기"
  - 최신순 = 늦게 쓴 것 먼저 / 등록순 = 먼저 쓴 것 먼저 / 추천순 = 👍 많은 순(같으면 최신순)
  - 펼쳤을 때 기본 정렬은 **추천순** (접힌 3개와 이어지게)
- 펼친 상태에서는 지금처럼 **20개씩 "댓글 더 보기"**
- 정렬을 바꾸면 처음부터 다시 불러옴. 고른 정렬은 이 브라우저에 기억(`localStorage`, try/catch로 감싸고 실패해도 동작)
- "접기"를 누르면 다시 상위 3개, 댓글 영역 제목으로 스크롤

### API
- `GET /api/games/{id}/comments`에 `sort=latest|oldest|top`(기본 `latest` — 기존 동작 유지) 추가, 그 외 값 422
- 다음 쪽 불러오기: 추천순은 같은 👍 수가 많아 `before_id`로는 안 됨 → **`cursor`**(서버가 주는 다음 쪽 표시 문자열, 화면은 그대로 돌려보내기만) 방식으로 바꾼다. 응답에 `next_cursor`(없으면 null). 기존 `before_id`는 `latest`에서만 계속 받기(호환)
  - `cursor`는 서버가 검증(형식·정렬 종류 일치), 잘못되면 422
- 접힌 화면은 `sort=top&limit=3` 한 번으로

### 테스트 (예)
세 정렬의 순서 / 추천순 동점 처리 / `cursor`로 끝까지 넘겨도 빠짐·중복 없음(댓글 45개, 추천 섞어서) / 잘못된 `sort`·`cursor` 422 / `limit=3` + `total` / 기존 `before_id` 호환
