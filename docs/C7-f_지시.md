# C7-f 작업 지시 (PROJECT.md 4.11의 C7-f와 같은 내용 — PROJECT.md가 덮여 지워졌을 때를 대비한 사본)

**C7-f. 최근 출시작 전부 수집 + 태그 적은 게임 % 보정 (11/9 채팅 결정)**
- 배경: 지금 새 게임은 인기·매출·유료 **차트 상위 100위 안**에서만 들어옴 → 차트에 못 오른 신작은 안 들어옴. 본인 결정: **"기준 없이 최근 출시작 다 넣고 지켜보자"** (설치 수·별점 수 기준 없음). 단 **출시 예정작은 제외, 출시된 것만**
- **1) 최근 출시작 수집 (`app/store_sync.py`, `scripts/sync_store.py`)**
  - App Store: C7-a2에서 버린 신작 피드 `itunes.apple.com/kr/rss/newapplications/limit=100/genre=6014/json`를 다시 쓰되, 받은 뒤 `lookup`으로 **장르가 게임(`primaryGenreId` 6014 또는 `genreIds`에 6014)인 것만** 남김 → 교육·외국 앱 섞임 문제 해결. 가능하면 무료·유료 신작 피드(`newfreeapplications`, `newpaidapplications`)도 같이 시도, 실패해도 계속
  - Google Play: 공식 신작 목록이 없음 → ① App Store 신작의 짝을 기존 방식(`bundleId` → 이름 검색)으로 찾음 ② Play 검색 "신작 게임"·"정식 출시"·"오픈" 등 키워드 몇 개(`data/new_release_queries.json`)로 찾은 게임 중 출시일이 최근인 것. 실제로 얼마나 잡히는지 Code가 확인해서 결과에 적기
  - **"최근"** = 출시 90일 이내 (신작 탭과 같은 기준, `reco_config` 또는 설정 상수 `NEW_RELEASE_DAYS=90`)
  - **출시 예정 제외 (엄격)**: iOS는 `releaseDate`가 오늘 이후면 제외(사전 주문). Play는 출시일이 없거나·설치 수 0·"사전 등록" 상태면 제외. 이미 들어온 게임 중 출시 예정으로 판정되는 게 있으면 목록에 보고(지우지는 않음)
  - **기준 없음**: 설치 수·별점 수 최소값 없이 다 넣음. 단 지금 있는 안전장치는 유지 — 카지노 제외, 같은 게임 판정·검수 대기, 요청 간격 1초, 하루 1번
  - 상한: 차트용 50개와 **따로** 신작용 상한 `NEW_RELEASE_MAX_PER_RUN`(기본 100)을 둠 → 차트 게임 때문에 신작이 밀리지 않게. 상한에 걸려 못 넣은 수는 로그·결과에 기록
  - **나중에 걸러낼 수 있게 표시**: 신작 경로로 들어온 게임은 `games.source_feed='new'`(차트 경로는 'chart', 수동은 'manual')로 저장. 나중에 기준을 정하면 `--prune-new --min-installs N --min-ratings N`으로 한 번에 숨길 수 있게(`review_status='rejected'`, 지우지 않음). 이번엔 옵션만 만들고 실행은 안 함
  - 실행 후 결과에 기록: 신작으로 새로 들어온 수(iOS만/Android만/두 스토어 짝), 출시 예정으로 제외한 수, 설치 수·별점 수 분포(0인 게임 몇 개인지), 자동 태그 수 분포 → 본인이 "지켜보고" 기준 정할 때 쓰는 자료
- **2) 태그 적은 게임 % 보정 (C7-e 결과의 ⚠ 해결)** — 기준 없이 넣으면 태그 2~3개짜리 게임이 더 늘어서 함께 처리
  - `coverage()`에 `min(1, 게임 태그 수 ÷ MATCH_MIN_TAGS)`를 곱함, `MATCH_MIN_TAGS=4` (`reco_config.py`). 태그 2개가 둘 다 취향이어도 최대 50%
  - C7-e 비교 표의 6명으로 다시 찍어서 "C7-e 후 → C7-f 후" 열 추가. Geometry Dash·파피 플레이타임이 퍼즐·캐주얼 취향에서 몇 %가 되는지 적기. 결과가 목표(잘 맞는 사용자 70% 이상 5~10개)와 크게 다르면 혼자 숫자 바꾸지 말고 보고
- 테스트: 신작 피드에서 게임 아닌 앱 제외 / 출시일 미래·사전 등록 제외 / 90일 넘은 게임 제외 / 신작 상한 따로 / `source_feed` 저장 / `--prune-new`가 지우지 않고 숨김 / 다시 실행해도 중복 없음 / 태그 2개 게임 % ≤ 50 / 기존 132개 통과
- **실제 DB에 실행**: 바꾸기 전 DB 백업을 `data/backup/`이 아닌 스크래치 폴더에 두고 경로를 결과에 적기 (C7-a2와 같은 방식)
