## C8-a. C7-f 후속: 취향 % 완화 + 신작 정리

### 1) 취향 % 완화 (C7-f 결과의 ⚠ 해결)
- 채팅 판단: 후보 3개(`MATCH_MIN_TAGS` 3 / 홈 60% / √ 완화)를 C7-f 숫자에 넣어 보면 **셋 다 Geometry Dash·파피 플레이타임(퍼즐·캐주얼 취향)이 다시 70% 또는 60% 기준을 넘음** (일치율 0.857·1등 대비 1.0 기준: MIN 3 → 70%, √ → 72%, 홈 60% → 60%로 통과). 즉 하나만 바꾸면 C7-f에서 고친 문제가 돌아옴
- 결정: **`MATCH_MIN_TAGS = 4`는 그대로**(화면 %는 정직하게) + 홈 슬라이드만 다음처럼 바꾼다
  - 홈 기준 70% → **60%** (`home.js`의 `MIN_MATCH`, 안내 문구의 숫자도 같이)
  - 홈 슬라이드의 **기준 통과 칸**에는 **태그 3개 이하 게임을 넣지 않는다** (`HOME_MIN_TAGS = 4`, `reco_config.py`). 대체 동작·탐색 칸에는 들어갈 수 있음
- 결과에 기록: C7-f 표의 6명으로 "C7-f 후 → C8-a 후" 기준 통과 개수, 그리고 시뮬 C 슬라이드에 Geometry Dash·파피 플레이타임이 나오는지. 목표(잘 맞는 사용자 5~10개, 실제 사용자 3개 이상)에서 크게 벗어나면 숫자 바꾸지 말고 보고
- 근본 해결은 태그를 늘리는 것(일정 3~4주차 태그 검수, 나중에 LLM 태깅) — 이번엔 안 함

### 2) 신작 검수 대기 17개 → iOS만으로 넣기 (C7-f 질문에 대한 결정: **예**)
- 규칙 변경: iOS 신작의 Android 짝을 **이름 검색으로만** 찾았고 개발사가 다르면 → 검수 대기로 보내지 말고 **iOS만 있는 게임으로 넣는다**. 검수 대기는 "DB에 이미 있는 게임과 이름이 비슷할 때"만
- 지금 대기 17개도 같은 규칙으로 다시 판정: 먼저 `--dry-run`으로 목록(이름, iOS·잘못 걸린 Android 앱 이름)을 결과에 적고, DB 게임과 겹치지 않는 것만 iOS만으로 넣기
- 블록 블라스트 ↔ 로블록스 대기 건은 다른 게임 → `--approve`(별개 게임으로 등록)

### 3) 신작 탭 정렬 (수집은 기준 없이 그대로)
- 문제: 신작 탭 맨 앞이 별점 0개인 해외 소형 앱 (예: Departure Rush, 터키어·일본어 제목)
- 수집·저장은 지금처럼 전부. **보여주는 순서만** 바꾼다: ① 이름에 한글이 있거나 별점 수 1개 이상인 게임 먼저 → ② 나머지. 각 그룹 안에서는 출시일 최신순
- 숨기지는 않음 (나중에 기준을 정하면 `--prune-new`로)

### 4) 라이징파이터

## C8-c. 상세 페이지 댓글

- C7-b(리뷰 + 체크 항목 집계)는 **계속 보류**. 이번엔 **자유 댓글**만
- **위치**: 상세 페이지 "별점" 아래, "비슷한 게임" 위. 제목 "댓글 N"
- **쓰기**: 한 사람이 여러 개 가능. 글 **1~300자**(앞뒤 공백 제거 후), 줄바꿈 허용(최대 10줄). 입력창 + 글자 수(예: 12/300) + 등록 버튼
- **목록**: 최신순 20개씩 "더 보기". 작성자 닉네임(없으면 "익명 사용자") · 시간("방금", "3분 전", "11/9") · 고친 글은 "(수정됨)". 내 댓글에만 고치기·지우기
- **DB** (`scripts/init_db.py`, 이미 있는 DB에도 붙게): `comments`(id INTEGER PK, game_id → games, user_id → users ON DELETE CASCADE, body TEXT NOT NULL, created_at, updated_at NULL), 인덱스 (game_id, created_at)
- **API**
  - `GET /api/games/{id}/comments?before_id=&limit=20` → `{ total, comments: [{id, nickname, body, created_at, edited, mine}], has_more }` (없는 게임 404, `limit` 1~50)
  - `POST /api/games/{id}/comments` `{body}` → 201 + 만든 댓글
  - `PATCH /api/comments/{id}` `{body}` / `DELETE /api/comments/{id}` → 내 댓글만 (남의 것 403, 없으면 404). 삭제는 실제 삭제
- **보안**
  - 서버에서 길이·줄 수 검사, 제어 문자 제거, 422로 거절
  - 요청 제한: 쓰기·고치기 합쳐 **사용자당 분당 5회, 하루 50회** (429)
  - 화면 출력은 `textContent` + CSS `white-space: pre-wrap` (HTML로 넣지 않음)
  - 기존 POST와 같은 보호(`app/security.py`의 쿠키·출처 검사 등) 그대로 적용
  - 마이페이지/설정의 "내 데이터 내려받기"에 댓글 포함, "내 데이터 삭제"하면 댓글도 삭제. "추천 기록 초기화"는 댓글을 지우지 않음
- **안 하는 것 (나중에)**: 신고·숨기기, 욕설 필터, 대댓글, 좋아요 → PROJECT.md 7장에 "(배포 전) 댓글 신고·관리 방법" 할 일로 추가
- 개인정보 처리방침 초안에 "댓글(닉네임과 함께 공개)" 항목 추가 (제출 전 검토 목록에 이미 있음)
