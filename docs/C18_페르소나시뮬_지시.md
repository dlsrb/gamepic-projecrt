# C18 지시 — 가상 사용자에 "인격(페르소나)" 넣어 다시 테스트 (11/23 채팅, 교수님 조언)

> `PROJECT.md`, `docs/C14_시뮬_지시.md`, `docs/sim_report.md`, `docs/sim_notes.md`와 같이 읽고 시작. 결과는 PROJECT.md 4.11 "결과 (C18)".
> 교수님 조언: 가상 사용자에게 **플레이 타임(하루 몇 시간), 좋아하는 장르, 싫어하는 장르**를 넣어 테스트해 볼 것.
> 이것은 **시뮬레이터 안의 가상 사용자 성격**일 뿐, 배포 사이트·실제 DB·화면에는 아무것도 추가하지 않음 (C14 절대 규칙 그대로: 실험 사본 DB에서만, 실제 DB·seed·zip·git에 가상 데이터 없음).
> 외부 AI API 없음, 시드 고정. C17(맞춤 추천 80%) 반영 뒤에 실행.

## 1. 페르소나 (가상 사용자 한 명마다)
- `play_time`: 하루 플레이 시간 — 0.5 / 1 / 2 / 3 / 5시간 이상 중 하나 (분포는 결과 표에)
- `likes_genres`: 좋아하는 장르 1~3개 (장르 8개 중)
- `dislikes_genres`: 싫어하는 장르 0~2개 (likes와 겹치지 않게)
- `likes_tags` / `dislikes_tags`: 장르 외 숨은 취향 태그 (C14 유형에서 물려받되 사람마다 조금씩 다르게)
- `persona_text`: 사람이 읽을 한 줄 설명 (예: "하루 30분, 퍼즐·캐주얼 좋아함, 전략 싫어함, 광고 싫어함") — 보고서용, 규칙으로 생성
- 300명(C14와 같은 인원)으로, 유형 비율은 C14와 비슷하게. 페르소나 전체를 `docs/sim_personas.csv`로 (가상 인물이라 개인정보 아님, 그래도 실명처럼 보이는 이름 쓰지 말고 `sim-0001` 같은 id만)

## 2. 페르소나가 행동에 주는 영향 (규칙은 표로 결과에 적기)
- **플레이 타임 → 방문·열람량**: 짧을수록 방문·상세 열람이 적음, 길수록 많음
- **플레이 타임 → 취향**: 짧은 사람은 `짧은플레이`·`방치형RPG`·`오프라인` 쪽에 끌림, 긴 사람은 `MMORPG`·`오픈월드`·`스토리중심` 쪽에 끌림 (숨은 선호 태그에 더함)
- **좋아하는/싫어하는 장르 → 설문 답**: 설문 3번·4번에 이 장르를 고름. 단 **일부(예: 20%)는 싫어하는 장르를 설문에 안 밝힘** (실제 사람처럼) → 엔진이 반응으로 배우는지 보려고
- 반응 확률은 C14 방식(숨은 취향과 게임 태그 겹침) + 숨은 싫어하는 장르 게임은 관심 없음 확률 높게

## 3. 재는 법 바꾸기 (sim_notes 1 제안 반영)
- "숨은 취향 일치"를 **겹치는 태그 2개 이상**으로 엄격하게 (C14의 1개 기준도 같이 보여 줘서 비교)
- **회차별 따봉률**을 그룹별(random/survey/feedback)로
- **안 밝힌 비선호 장르**가 추천에 나온 비율이 회차가 갈수록 줄어드는지 (feedback 그룹이 배우는지 핵심 지표)
- **플레이 타임별**: 짧은/긴 사람에게 추천된 게임의 `짧은플레이`·`MMORPG` 등 비율 → 엔진이 플레이 시간 성향을 따라가는지
- C17 이후 홈 맞춤 칸(80% 이상) 장 수 분포도

## 4. 실행
- 두 DB에서 각각: ① 지금 실제 규모 사본(`sim.db`, 게임 ~280) ② 규모 실험 DB(`big.db`, C16 끝났으면, 게임 ~1,500)
- `python scripts/simulate_users.py --persona --users 300 --seed 42 --days 14 [--db ...]` (옵션 이름은 지금 구조에 맞게)
- 보고서 `docs/persona_report.md` (맨 위 "시뮬레이션, 실제 피드백 아님"): C14 결과와 나란히, 위 3번 지표 중심. 발견한 문제는 **고치지 말고 제안**
