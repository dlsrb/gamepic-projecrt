# C14 지시 — 가상 사용자 300명 시뮬레이션 (로컬 전용) (11/23 채팅)

> `PROJECT.md`와 같이 읽고 시작. 결과는 PROJECT.md 4.11 "결과 (C14)", 지시 외 결정은 따로.
> 목적: 사용자가 많을 때 추천·랭킹·이달의 게임·검색·댓글이 제대로 도는지, 느려지지 않는지 **로직 점검**. 실제 사용자 피드백이 아님.
> **절대 규칙**
> - 실제 DB(`data/gamepick.db`)·`data/seed.db`·배포 zip에는 가상 데이터가 **한 줄도 들어가면 안 됨**. 전용 사본 `data/sim.db`에서만 (`.gitignore`에 추가)
> - 가상 사용자·댓글은 화면·API·MCP 어디에도 실제 데이터처럼 섞여 보이지 않게. 결과 보고서에는 "시뮬레이션"이라고 명시
> - 외부 AI API 호출 없음 (비용·키 없음). 행동은 규칙 + 무작위(시드 고정)

## 1. 시뮬레이터 `scripts/simulate_users.py`
- `python scripts/simulate_users.py --users 300 --seed 42 --days 14` → `data/gamepick.db`를 `data/sim.db`로 복사한 뒤 거기서만 실행 (이미 있으면 덮어쓸지 물음, `--force`)
- 앱 코드는 **실제 API를 거쳐서** 호출 (FastAPI TestClient, 사용자마다 쿠키 따로) → 실제 사용자와 같은 경로 점검. DB 경로는 환경 변수로 `sim.db`
- 요청 횟수 제한·IP당 사용자 생성 제한은 시뮬에서만 끄거나 넉넉히 (설정으로, 코드에 박지 않음)
- 가상 사용자 표시: `users`에 `is_sim` 컬럼이 없으면 시뮬 DB에서만 쓰는 표로 id를 따로 기록 (실제 DB 구조는 바꾸지 않는 쪽 우선, 바꾸면 결정에 적기)

## 2. 가상 사용자 만들기 (페르소나)
- 300명을 취향 유형 8~10개로 나눔 (예: RPG 수집러, 퍼즐·힐링, 경쟁 PvP, 인디·감성, 방치형, 전략·SLG, 캐주얼 가볍게, 넓은 취향, 무과금 선호, 까다로운(비선호 많음)). 유형별 인원 비율은 결과에 표로
- 설문은 **실제 설문 API**로 제출: 유형에 맞게 3번(좋아하는 장르·키워드), 4번(비선호, 20%는 "딱히 없어요"), 5번(좋아하는 게임 0~3개), 나머지 문항은 유형별 확률
- 실험 그룹(`exp_group`: random/survey/feedback)은 기존 배정 규칙 그대로 → 그룹별 비교 가능하게

## 3. 행동 (14일, 사용자마다 방문 1~10회)
- 방문마다: 홈 맞춤 추천·이달의 게임·랭킹 중 일부를 보고 → 상세 몇 개 열람
- 반응 확률은 **그 사용자의 "숨은 진짜 취향"**(페르소나 태그)과 게임 태그의 일치로 정함 (화면의 취향 %를 그대로 쓰지 않음 — 엔진이 맞혔는지 따로 보려고)
  - 잘 맞으면 따봉·스토어 이동 확률 ↑, 안 맞으면 관심 없음 ↑
  - 같은 게임 따봉 1회 등 기존 규칙은 API가 지키는지 확인
- 검색: 방문의 30%에서 1회 (유형에 맞는 단어 + 이름 일부 + "인디·신작·급상승" 같은 배지 단어)
- 댓글: 전체 약 300개. **문장 틀(템플릿) + 태그 단어 조합**으로 만든 짧은 문장 (예: "{태그}라서 출퇴근에 하기 좋아요", "과금 유도가 좀 있어요"). 욕설·개인정보 없음. 댓글 추천/비추천도 일부
- 날짜를 14일에 나눠 기록할 수 있으면 나누고(반응·댓글 created_at), 안 되면 결정에 적기

## 4. 보고서 `docs/sim_report.md` (시뮬레이션이라고 맨 위에 명시)
1. **추천 적중**: 그룹별(random/survey/feedback) 홈 맞춤 추천의 따봉률·관심 없음률, 숨은 취향과의 일치율. 피드백 그룹이 방문할수록 나아지는지(방문 회차별)
2. **비선호 위반**: 비선호(연관 포함) 태그 게임이 맞춤 추천·이달의 게임에 나온 횟수 → 0이어야 함
3. **다양성·쏠림**: 추천에 한 번이라도 나온 게임 수 / 전체, 상위 10개 게임이 추천 노출에서 차지하는 비율, 탐색 칸 무작위가 쏠림을 줄이는지
4. **검수 상태별**: human·ai·store·auto 게임이 추천에 나온 비율과 따봉률
5. **랭킹·이달의 게임 변화**: 시뮬 전/후 추천 순위(따봉) 상위 10, 이달의 게임 구성
6. **검색**: 결과 0개였던 검색어 목록, 이름 일부 검색 성공률
7. **속도**: 주요 API(홈 추천, 검색, 상세, 랭킹) 응답 시간 중앙값·95% (사용자 4명일 때 vs 300명 후)
8. **발견한 문제**: 위에서 이상한 것 → 원인 추정, 고칠지 제안 (**고치지는 말고** 보고)
- 표·숫자 위주, README·발표에 옮길 수 있게. 그래프가 있으면 PNG로 `docs/sim/`
