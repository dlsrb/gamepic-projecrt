## 리뷰 데이터 분석 (구 트랙 A)

### 3.1 스토리라인
제목(가제): **「별점이 말하지 않는 것 — 문장 단위 감정 분석으로 본 모바일 게임 리뷰의 실제 반응」**

핵심 주장: 별점은 리뷰를 숫자 하나로 압축해 정보를 잃는다. 문장 단위로 나누면 별점이 숨기는 불만이 보인다.
(예: "스토리 좋아요. 근데 과금 유도가 심해요. 그래도 5점" → 긍정 2, 부정 1)

| 연구 질문 | 가설 |
|---|---|
| RQ1 별점과 문장 감정은 얼마나 어긋나는가 | H1 4~5점 리뷰에도 부정 문장이 의미 있는 비율로 있다 |
| RQ2 고별점 리뷰 속 부정 문장의 주제는 | H2 과금·광고에 집중된다 |
| RQ3 대형 vs 인디 불만 주제 차이 | H3 대형은 과금·운영, 인디는 버그·최적화 |
| RQ4 평가와 무관한 문장 비율 | H4 '관계없음' 비율이 무시할 수 없는 수준 |
| RQ5 Android vs iOS 불만 차이 | H5 Android에서 발열·최적화 불만 비중이 더 높다 |

### 3.2 데이터 수집
- **게임 약 100개**, 8~10개 장르. 설치 수 기준 대형 30 / 중견 40 / 인디 30
- **Google Play (주 데이터)**: 대형 게임당 최대 1,000(수집은 1,500), 중견 400(수집 600), 인디 전량. `google-play-scraper`, ko/kr, 최신순, 최근 12개월
- **App Store (보조 데이터)**: 공개 고객 리뷰 RSS 피드, 게임당 최근 일부(약 500건, 실제 수집 후 확인). 제목+본문 합침
- **기준 수량**: 전처리 후 **25,000건 이상** (Google Play만으로 충족)
- 개인정보(닉네임, 프로필) 저장 안 함

**출력 형식 (Gemini 크롤러와 합의된 규격)**
- 입력: `data/game_list.csv` — `game_id, name, tier, genre, android_id, ios_id`
- 출력: `data/raw/android/{game_id}.csv`, `data/raw/ios/{game_id}.csv`
- 컬럼: `platform, game_id, review_id, content, score, date(YYYY-MM-DD), app_version, thumbs_up, has_reply`
- 로그: `logs/failed.txt`, `logs/summary.csv`

### 3.3 전처리
중복 제거 → 결측 제거 → 짧은 리뷰(공백 제외 10자 미만) 제거 → 정규화(반복 문자 축약, URL·쿠폰코드 마스킹, **탭·줄바꿈 → 공백**) → `kss`로 문장 분리

### 3.4 라벨링
- 단위: **문장 1개 = 라벨 1개**
- 라벨: **0=부정, 1=긍정, 2=중립, 3=관계없음** (기존 이진 분류 의미 유지)
- 경계 규칙: 혼합 문장은 대비 접속(~는데, ~지만) 뒤 기준 / 반어는 실제 의미 / 불만 담긴 건의=부정, 단순 건의=중립 / 게임 관련 질문=중립, 무관한 문의=관계없음
- 과정: 파일럿 200문장(직접) → 층화 추출 약 3,000문장(게임별·별점별 균등, App Store 15~20%, 중립·관계없음 보충) → Gem 1차 → 전수 검수 → Gem–최종 일치율 기록 → (선택) Cohen's kappa
- 주제(과금·광고·버그·발열·운영)는 라벨이 아니라 **분석 단계의 키워드 사전 후처리**

### 3.5 모델 (수업 코드 `KOELECTRA-Finetune.py`)
- 입력: 탭 구분 `id, document, label` (NSMC 형식)
- 4분류를 위해 `num_labels=2 → 4` 변경 필요 (**교수님 허용 여부 확인 필요**)
- 코드는 정확도만 계산, 토크나이저 미저장, 8:2 비층화 분할(`random_state=2026`) → 평가·추론은 별도 스크립트로
- 플랫폼·게임·별점 메타데이터는 학습 파일과 분리해 `data/review_sentences_meta.csv`에 `id` 기준 저장
