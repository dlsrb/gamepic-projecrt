## C11-a. 배포 때 생긴 문제를 코드에 반영
1. `requirements.txt` 끝에 추가 (Replit 보안 검사가 critical 취약점으로 배포 차단했음):
   ```
   anyio>=4.14.2
   certifi>=2026.10.18
   ```
2. `scripts/pack_for_replit.py`: Replit에서 zip을 풀 때 `docs/`의 한글 파일 이름이 깨져 배포가 `invalid UTF-8`로 실패함 → **zip에서 `docs/`를 뺀다** (실행에 필요 없음). 그 밖에 zip 안 파일 이름이 ASCII가 아니면 묶기 전에 오류로 멈추게 + 테스트
3. **아이폰 스토어 버튼**: 아이폰 Safari, 소울 나이트 상세에서 카드를 누르면 App Store가 안 열리고 게임픽 페이지가 새로고침됨
   - 배포본 zip이 C10-a 이전 것일 수 있음(본인이 다음 배포 때 최신 zip으로 확인). 그래도 코드 쪽 원인을 찾아 고칠 것
   - 확인할 것: `soulknight`의 `ios_url` 값, `window.open(url, "_blank", "noopener")`가 iOS Safari에서 막히거나 같은 탭을 새로고침하는 경우, 카드가 `<a>`/`<button>` 기본 동작으로 페이지를 다시 여는지
   - 고치는 방향: iOS는 `location.href = ios_url`(같은 탭에서 App Store로 넘김) 또는 `<a href target="_blank" rel="noopener">`로. 스토어 이동 기록(+0.5)은 이동 전에 `navigator.sendBeacon` 등으로 남김
4. App Store 링크 남은 8개(C10-a 결과 목록)는 그대로 두고 목록만 결과에 다시 적기 (본인 확인 후 넣음)

## C11-b. 로고 + 왼쪽 위 홈 버튼
- 서비스 영문 표기를 **GamePick / 로고 GAMEPICK**으로 통일 (화면에 "GAMEPIC"이 있으면 고침)
- 모든 페이지 상단 왼쪽에 로고, **누르면 홈**(`/`). 설문 진행 중에는 홈으로 가면 설문이 안 끝나므로, 설문 페이지에서는 로고를 눌러도 이동 안 하거나 "설문을 그만둘까요?" 확인
- 로고는 **이미지가 아니라 글자(CSS 또는 인라인 SVG)**. 굵고 각진 고딕 계열, 글꼴 파일을 새로 받지 말고 지금 글꼴(나눔스퀘어라운드 EB) 또는 시스템 굵은 고딕으로
  - 라이트: **GAME = 남색**(기존 색 체계의 남색 계열), **PICK = 밝은 회청색 채움 + 남색 얇은 테두리** → 흰 배경에서도 또렷하게 (시안은 PICK이 흐려서 안 보였음)
  - 다크: GAME = 흰색 또는 밝은 남색, PICK = 밝은 회청색 (어두운 배경에 남색이 묻히지 않게)
- 기존 상세 오른쪽 위 "홈" 버튼이 하단 메뉴와 겹친다는 열린 질문(C8-b)이 있음 → 로고가 홈 역할을 하므로 **오른쪽 위 홈 버튼은 뺌**

## C11-c. 랭킹 페이지의 추천 순위
- 지금: 동그라미 안 숫자 + 게임 이름 + 👍 이모지·숫자
- 바꿀 것:
  - 각 줄: **순위 숫자(동그라미 없이 숫자만, 1~3위는 굵게 정도)** · **썸네일(정사각, 모서리 둥글게)** · **제목** · **제목 아래 한 줄 설명**(게임 설명 첫 문장, 한 줄 넘치면 말줄임) · 오른쪽에 추천 수
  - 👍 이모지 대신 **선 아이콘(인라인 SVG 엄지)** + 숫자. 이모지는 이 목록에서 쓰지 않음
  - 줄을 누르면 상세로
- 썸네일 없으면 기존 대체 표시, 설명 없으면 장르·태그 2개로 대신
- API에 필요한 필드(썸네일, 한 줄 설명)가 없으면 랭킹 API 응답에 추가 (기존 필드는 그대로)

## C11-d. 신작 페이지
- **2026년작 / 2025년작** 두 칸(섹션)으로 나눔 — `release_date` 연도 기준. 그 외 연도·날짜 없음은 맨 아래 "그 밖의 게임" (없으면 칸 숨김)
- **필터**: 버튼을 누르면 열리는 영역 안에 **장르 칸**(genre 태그 8개)과 **키워드 칸**(subgenre·play·mood·view·bm 태그)을 **따로** 보여 줌. 여러 개 선택 가능
  - 장르끼리는 OR, 키워드끼리는 AND? → **장르는 하나라도 맞으면(OR), 키워드는 고른 것이 모두 있어야(AND)**, 장르와 키워드는 AND
  - 고른 필터는 상단에 칩으로 보이고 X로 하나씩 끄기, "초기화"
  - 필터 적용 후 비면 "조건에 맞는 신작이 없어요"
- 필터는 서버 API(쿼리 파라미터)로 할지 화면에서 거를지는 데이터 양 보고 결정 (결정에 적기)

## C11-e. 비선호 제외 강화 (추천·홈·검색·비슷한 게임 공통)
- 증상: 설문에서 캐주얼·퍼즐을 싫어한다고 했는데 "귀여움" 태그 게임이 추천됨
- **연관 태그표**를 `data/dislike_related.json`으로 새로 만들고, 비선호로 고른 태그 + 그 연관 태그가 붙은 게임을 모두 후보에서 제외
- 초안 (Code가 태그 목록 보고 다듬어도 됨, 바꾼 것은 결정에 적기):
  - 장르 → 그 장르의 세부 장르 전부 (예: 퍼즐 → 매치3·감성퍼즐 / RPG → 턴제RPG·액션RPG·MMORPG·수집형RPG·방치형RPG·로그라이크RPG / 캐주얼 → 러너·파티)
  - 캐주얼 → **귀여움**도 포함 (본인 요청)
  - 그 밖의 장르↔분위기 연결은 넣지 않음 (넓히면 후보가 바닥남)
- **적용 전/후 표**를 결과에 남김: 시뮬 사용자(캐주얼·퍼즐 비선호, 그 외 C7-d의 시뮬 A·B·C·E)별 추천 후보 수, 홈 슬라이드 장 수. **후보가 9개 미만이 되는 사용자가 생기면 혼자 기준을 바꾸지 말고 표와 함께 보고**
- 기존 사용자도 다음 요청부터 바로 적용(설문 다시 할 필요 없음)

## C11-f. 설문 간소화 (3·4·5번 문항)
문제: 선택지가 한 화면에 너무 많아 보기 힘들고 하기 싫어짐.
- 3번(좋아하는 장르·키워드)·4번(싫어하는 것) 공통:
  - 기본으로 **대표 장르 5개 + 대표 키워드 5개만** 보여 줌
    - 장르 기본값: RPG · 액션 · 퍼즐 · 시뮬레이션 · 캐주얼
    - 키워드 기본값: 힐링 · 귀여움 · 판타지 · 스토리중심 · PvP (4번은 PvP·가챠·광고·자동전투·호러 계열이 있으면 그쪽 우선 — Code가 태그 목록 보고 제안)
    - 기본값은 `data/survey.json`에 두고 코드에 박지 않음
  - **검색창**: 장르·키워드 전체에서 이름으로 찾기(부분 일치, 동의어 `search_synonyms.json` 재사용). 검색해서 고른 것도 위 칩 목록에 추가되어 보임
  - "더 보기"로 전체 목록을 펼치는 버튼은 남겨도 됨 (접힌 상태가 기본)
- 5번(재밌게 한 게임):
  - 3번에서 고른 장르·키워드에 맞는 **대표작 3개만** 기본 노출 (부합도·추천 수·설치 수 순으로 고르기, 기준은 결정에 적기)
  - **게임 검색창** 추가 (이름 부분 일치, 기존 검색 API 재사용 가능). 최대 3개 선택 규칙은 그대로
- 문항 수·점수 규칙(4.12, 4.1)은 바꾸지 않음. 보여 주는 방식만 바꿈
- 모바일 375px에서 한 화면에 선택지가 넘치지 않는지 확인
