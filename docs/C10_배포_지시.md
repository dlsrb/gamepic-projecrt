## 결정 사항 (11/16 채팅)
- **DB: SQLite 그대로 + Replit Object Storage에 자동 백업·복원** (PostgreSQL 이전은 하지 않음 — PROJECT.md 7장 "DB 영속화 방식" 결정 완료)
- **배포 방식: Reserved VM**(서버 1대 항상 켜짐). 이유: SQLite 파일 1개, 메모리 속 요청 제한, 서버 안 하루 1번 스토어 수집 스레드가 모두 "서버가 1대·계속 켜짐"을 전제로 함 → Autoscale(여러 대·잠들기)과 안 맞음
- Replit 계정은 과목용 **Core** 계정. Reserved VM은 월 사용량(크레딧)을 씀 → 본인이 배포 화면에서 가장 작은 사양을 고르고 비용 확인

## 0단계 (Code가 먼저): Replit 현재 문서 확인
채팅에서는 최신 문서를 확인하지 못했다. 아래를 Replit 공식 문서(docs.replit.com)에서 확인하고 결과 맨 위에 적는다. 이 지시와 다르면 **구현 전에 보고**.
1. 배포(Deployment)의 파일 시스템이 재배포·재시작 때 초기화되는지
2. Reserved VM에서 앱이 들어야 하는 포트·호스트(예: `0.0.0.0` + 지정 포트), 헬스 체크 경로 설정
3. Object Storage 파이썬 라이브러리 이름·사용법(예: `replit-object-storage`, `from replit.object_storage import Client`)과 배포 환경에서 인증이 자동인지
4. 배포에서 Secrets(환경 변수) 넣는 방법, `.replit` 파일의 `[deployment]` 실행 명령 형식
5. 요청이 Replit 프록시를 거칠 때 실제 사용자 IP가 오는 헤더(`X-Forwarded-For` 등)

## 1단계: 코드 준비 (로컬에서, 로컬 동작은 그대로 유지)

### 1) 실행 설정
- `.replit`(필요하면 `replit.nix`): 개발 실행 = `python app/main.py`, **배포 실행 = uvicorn을 `0.0.0.0` + Replit 포트로, `--proxy-headers`** (프록시 뒤 실제 IP 사용, 신뢰 범위는 0단계 5번 결과대로)
- `config.py`는 그대로 환경 변수로: 배포 Secrets = `HOST=0.0.0.0`, `PORT`(Replit 값), `DEBUG=false`, `COOKIE_SECURE=true`, `STORE_SYNC=true`, `BACKUP=true`, `DB_PATH`(기본값 그대로 가능)
- `requirements.txt`에 Object Storage 라이브러리 추가(버전 고정). 로컬에서는 설치 안 돼도 서버가 켜지게(가져오기 실패 → 백업 끔 + 경고 한 줄)
- `.env.example`에 `BACKUP=` 설명 추가

### 2) DB 자동 백업·복원 (`app/backup.py`, `BACKUP=true`일 때만)
- **서버가 켜질 때**: DB 파일이 없으면 Object Storage의 `gamepick-latest.db`를 받아서 복원 → 없으면 아래 3)의 시작용 DB로 시작. 이미 DB가 있으면 건드리지 않음
- **10분마다**: 마지막 백업 뒤 바뀐 게 있으면 백업. SQLite **`Connection.backup()`**으로 임시 파일에 일관된 사본을 만든 뒤 `gamepick-latest.db`로 올림 (DB 파일을 그대로 복사하지 않음)
- **하루 1번**: `gamepick-YYYYMMDD.db`로도 올리고 **14일 지난 것은 삭제**
- **서버가 꺼질 때**(FastAPI lifespan 종료): 마지막으로 한 번 더 백업
- 백업 실패는 로그만 남기고 서버는 계속. 연속 실패 수·마지막 성공 시각을 `/api/health`에 `backup` 항목으로 (DEBUG=false에서도 숫자만, 경로·키 없이)
- 수동 명령: `python scripts/backup_db.py --now` / `--list` / `--restore 날짜` (복원 전 현재 DB를 `gamepick-before-restore-…`로 먼저 올림)

### 3) 시작용 DB (테스트 사용자 없이)
- `python scripts/make_seed_db.py` → `data/seed.db` 생성: 지금 로컬 DB에서 **게임·태그·스토어 정보만** 복사하고 사용자·반응·댓글·추천 기록·검색 기록은 비움. 검수 대기·제외 게임 상태는 유지
- 처음 배포 때 이 파일을 올려서 시작(복원할 백업이 없을 때). `data/seed.db`는 `.gitignore`의 `data/*.db`에 걸리므로 올리는 방법은 1단계 6) 압축에 포함

### 4) 게임 아이콘
- `static/img/games/`는 저작권 때문에 저장소에 안 올림(기존 결정). 서버가 켜질 때 아이콘이 없는 게임이 있으면 **별도 스레드로** 내려받기(`fetch_game_meta`의 아이콘 부분 재사용, 요청 간격 1초). 받는 동안은 기존 대체 표시(첫 글자 카드)

### 5) 공개 전 보안 (PROJECT.md 7장의 "배포 전" 항목)
- **IP당 사용자 생성 제한**: 쿠키 없는 요청으로 새 사용자를 만들 때 **IP당 1시간 20명**(`USER_CREATE_PER_HOUR`), 넘으면 429. IP는 프록시 헤더 기준(위 1) `--proxy-headers`)
- 기존 IP 기준 요청 제한들도 프록시 헤더의 실제 IP를 쓰는지 테스트로 확인 (전부 같은 IP로 세지 않게)
- **출처 검사**(C8 지시 외 결정 9번): 쓰기 요청(POST·PUT·PATCH·DELETE)에 `Origin`이 있으면 우리 주소와 같을 때만 허용, 다르면 403. 허용 주소는 환경 변수 `ALLOWED_ORIGINS`(쉼표 구분, 로컬 기본값 `http://127.0.0.1:8000,http://localhost:8000`)
- `DEBUG=false`에서 `/docs` 닫힘, 오류 응답에 내부 경로·코드 안 보임 확인
- 쿠키 `Secure`(COOKIE_SECURE=true) + `SameSite=lax` + `HttpOnly` 그대로

### 6) 올릴 파일 묶기
- `python scripts/pack_for_replit.py` → `dist/gamepick_replit.zip`: `.gitignore`에 걸린 것(`.env`, DB, 아이콘, 로그, `.idea` 등)과 `legacy/`, `dist/`는 빼고, **`data/seed.db`는 포함**. 묶은 파일 목록과 크기를 출력
- (GitHub 저장소가 아직 없음 — 폴더에 `.git` 없음. GitHub로 올릴지는 본인이 결정. 올린다면 비공개 저장소)

### 테스트 (예)
백업: 바뀐 게 없으면 안 올림 / `backup()` 사본이 열리고 내용 같음 / 14일 지난 것 삭제 / 실패해도 서버 계속 / DB 없을 때 복원 → 없으면 seed (Object Storage는 가짜 객체로 대체) · seed DB에 사용자·댓글 0, 게임 수 같음 · IP당 사용자 생성 429 · 프록시 헤더의 IP로 셈 · 출처 다르면 403, 같거나 없으면 통과 · 라이브러리 없을 때 서버 켜짐

## 2단계: 본인이 Replit에서 할 일 (Code가 결과에 순서대로 다시 정리해 줄 것)
1. Replit 로그인 → 새 앱(Python) 만들기 → `dist/gamepick_replit.zip` 내용 올리기 (또는 GitHub 가져오기)
2. **Object Storage** 켜기 (버킷 만들기)
3. **Secrets**에 1단계 1)의 값 넣기 (`ALLOWED_ORIGINS`는 배포 주소가 나온 뒤 추가)
4. 개발 화면에서 한 번 실행해 홈이 열리는지 확인
5. **Deploy → Reserved VM**, 가장 작은 사양, 비용 확인 후 배포 → 나온 주소(`○○.replit.app`)를 `ALLOWED_ORIGINS`에 넣고 다시 배포

## 3단계: 배포 확인 (본인 + Code)
- 내 폰(LTE)·친구 폰에서 주소 접속 → 설문 → 홈 → 상세 → 따봉·댓글·댓글 추천
- **다시 배포**한 뒤 위에서 남긴 따봉·댓글이 그대로인지 (백업·복원 확인) — 가장 중요
- 아이콘이 몇 분 안에 채워지는지, 다음 날 스토어 자동 수집 기록(`sync_runs`)이 생기는지
