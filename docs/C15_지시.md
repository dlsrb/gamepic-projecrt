## 고치는 것 (sim_notes 2·3·4번)

### C15-a. "급상승" 기록 부족 안내 (sim_notes 2)
- 스냅샷이 7일 미만이라 급상승 배지가 없는 동안:
  - 검색어 "급상승"(과 동의어) → 결과 0개 대신 **안내 문구** + 그 아래 "인기" 배지 게임을 대신 보여 줌. 안내 예: "급상승은 기록이 7일 쌓이면 보여요 (지금 N일). 대신 인기 게임을 보여 드려요"
  - 랭킹·홈 등 급상승을 보여 주는 다른 곳도 같은 안내로 통일 (지금 "기록 쌓는 중" 문구가 있으면 그것과 맞춤)
  - MCP `get_rankings(kind="surge")`, `search_games("급상승")`도 같은 상태를 알려 주게 (결과에 `note`)
- 7일이 차면 자동으로 원래 동작 (테스트로 날짜 조작해 확인)

### C15-b. 여러 단어 검색이 0개일 때 "일부만 맞는 게임" (sim_notes 3)
- 지금 규칙(모든 단어를 만족 = AND)은 그대로 먼저
- **AND 결과가 0개일 때만**: 단어 중 **하나 이상** 맞는 게임을 "일부만 맞는 게임"으로 보여 줌
  - 정렬: 맞는 단어 수 많은 순 → 취향 % 순
  - 카드마다 어떤 단어가 맞았는지 작게 표시 (예: "감성 ✓ · 스토리중심 ✗" 대신 담백하게 "감성만 맞음")
  - 화면 위에 "모두 맞는 게임이 없어 일부만 맞는 게임을 보여 드려요" 한 줄
  - 비선호 제외 규칙은 C12-k 그대로 (태그·동의어·배지로 찾은 결과에만, 이름 일부 일치는 남김)
- 단어 1개 검색, AND 결과가 1개 이상이면 지금과 똑같이
- 자동완성은 바꾸지 않음
- MCP `search_games`도 같은 규칙 (결과에 `partial: true`와 단어별 일치)

### C15-c. 이달의 게임에 게임픽 따봉 반영 (sim_notes 4)
- 지금 식(인기 0.6 + 급상승 0.3 + 취향 0.1)에 **이번 달 게임픽 따봉 수**를 약하게 더함. 예: 인기 0.55 + 급상승 0.25 + 따봉 0.1 + 취향 0.1. 무게는 `reco_config.py`, 최종 값은 결정에 적기
- 따봉 수는 이번 달(로컬 시간 기준 1일~) 것만, 게임별 최대값으로 나눠 0~1
- **가상 사용자 데이터가 실제 DB에 섞일 일은 없지만**, 계산은 실제 DB `reactions`만 봄 (sim.db에서 돌릴 때만 시뮬 데이터 반영)
- 비선호 제외·홈 인기 랭킹 5개 제외 규칙 그대로
- `python scripts/simulate_users.py --report-only`로 sim.db 기준 이달의 게임이 시뮬 전/후 달라지는지 보고서에 한 줄 추가 (시뮬 다시 돌리지 않음)
